# Практическая работа №2 — запуск Windows EXE

Артефакт GitHub Actions: `windows-x64-executables`.

## Как запустить на Windows x64

1. Скачайте ZIP-артефакт из успешного запуска **SecureFileManager CI/CD** и распакуйте **всю** папку.
2. Запустите `start-server.cmd` и **не закрывайте** окно. Сервер доступен только локально по адресу `http://127.0.0.1:5050`.
3. Проверьте в браузере `http://127.0.0.1:5050/api/health`: ожидается `{"status":"ok"}`.
4. Запустите `start-client.cmd` во втором окне.
5. Зарегистрируйтесь, войдите, создайте JSON, прочитайте файл, затем попробуйте прочитать несуществующий файл, чтобы увидеть понятную ошибку.
6. Чтобы остановить программу, закройте клиент и завершите сервер сочетанием Ctrl+C.

Файлы `server/FileManager.Server.exe` и `client/FileManager.Client.exe` опубликованы для Windows x64 с `--self-contained true` и не требуют отдельной установки .NET Runtime. Не удаляйте остальные файлы в папках, поскольку приложение может использовать их при выполнении.

Данные пользователей и SQLite создаются на стороне сервера рядом с исполняемым приложением в `server/ManagerData/`. Не публикуйте этот каталог и не храните его в Git.

## Что демонстрировать преподавателю

1. `git push` → GitHub **Actions** → новый запуск workflow.
2. Успешные задачи: Build, Test, SAST - Semgrep, Dependency Security - Trivy, Docker Deploy Smoke Test, Windows EXE.
3. Артефакты `test-results-and-coverage`, `semgrep-sast-report`, `trivy-dependency-report`, `server-and-client-builds` и `windows-x64-executables`.
4. Запуск `start-server.cmd`, проверка `/api/health`, запуск `start-client.cmd`.
5. Положительный сценарий: создать и прочитать JSON.
6. Отрицательный сценарий: запрос отсутствующего файла → понятное сообщение «Файл не найден».

Сканирование не гарантирует отсутствие уязвимостей. Windows EXE публикуется из CI только при успешном выполнении предшествующих заданий. Это учебный локальный проект — запуск в публичной сети без HTTPS не предусмотрен.
